# Webtoon MT Judge

만화 · 웹툰 기계 번역(MT, 일→한)을 LLM/VLM이 채점할 때, **그 점수가 사람 판단과 얼마나 맞는지**를 재본 작은 실험입니다.

Kimura & Suzuki의 [*Text-Only vs. Image-Aware VLM Judges for Manga Translation Evaluation*](https://arxiv.org/abs/2610.17908)은 같은 VLM에 페이지 이미지를 보여 줄 때와 보여 주지 않을 때의 판정을 비교했지만, 판정과 사람 평가의 일치도는 수치로 보고하지 않았습니다. 이 실험은 그 설계를 작은 규모로 옮기고, 빠진 **판정–사람 일치도**를 측정합니다.

## 설계 (결과를 보기 전에 고정)

| 항목 | 내용 |
|---|---|
| 데이터 | OpenMantra (CC BY-NC 4.0), 5개 작품 7쪽 · 말풍선 40개. 고정 시드로 선택 (`src/select_pages.py`) |
| 인물 관계표 | 쪽마다 인물 · 관계 · 원문의 경어 수준을 정리한 설정 자료(`data/context.json`). 번역 시스템은 보지 않고, 판정 모델과 사람 평가자만 봄 |
| 번역 시스템 | S1 Claude Opus · 페이지 이미지 + 쪽 단위 / S2 Claude Haiku · 페이지 이미지 + 쪽 단위 / S3 Claude Sonnet · 이미지 없이 한 줄씩 |
| 자동 판정 | Claude Sonnet, Claude Opus × {텍스트만, 페이지 이미지 포함}. 참조 번역 없이 원문 + 인물 관계표로 1~5점 + 오류 태그 |
| 사람 평가 | 1명(작성자), 시스템을 가린 블라인드 평가표, 같은 1~5점 기준 + 인물 관계표. 평가자는 일본어 대신 공식 영어 번역(참조)으로 뜻을 확인 |
| 일관성 점검 | 8개 말풍선을 끝에 다시 섞어 넣어 평가자 자신의 재평가 일치도 측정 |
| 지표 | 말풍선×시스템 단위 Spearman · Kendall, 같은 말풍선 안 두 번역의 우열 일치율(pairwise accuracy), 말풍선 단위 부트스트랩 95% 구간 |

## 설계를 바꾼 이유

처음에는 인물 관계 정보 없이 평가했지만, 평가를 시작해 보니 쪽 하나만으로는 인물 관계를 알 수 없어 **반말 · 존댓말이 맞는지 판단할 수 없었습니다.** 한국어 번역에서 경어 수준은 품질의 핵심이라, 관계를 모른 채 내린 점수는 사람의 것이든 모델의 것이든 믿기 어렵습니다. 그래서 실제 현지화 작업의 설정 자료처럼 쪽마다 인물 관계표를 만들어 판정 모델과 평가자에게 똑같이 주고 다시 평가했습니다. 관계표 없이 돌린 첫 판정은 `runs/v1_before_tone_rule/`에 남겨 두었습니다.

## 실행 방식

이번 결과의 번역과 판정은 **Claude 모델을 에이전트 세션에서 같은 프롬프트(`prompts/`)로 실행**해 만들었습니다(API 키 없이 진행). 각 모델은 자기 입력 파일만 보도록 분리했고, 판정 모델은 시스템 이름과 참조 번역을 보지 못했습니다. API로 다시 돌리거나 다른 모델(예: HyperCLOVA X)을 추가할 때는 `src/run_api.py`를 씁니다.

```
python src/select_pages.py <open-mantra-dataset 경로>   # 평가셋
python src/blind.py                                     # 번역 결과 섞기 → judge_input.json
python src/build_sheet.py                               # 사람 평가표
python src/analyze.py                                   # 일치도
```

## 결과

사람 평가 120개(말풍선 40 × 번역 3) 기준입니다. 구간은 말풍선 단위 부트스트랩 95%입니다.

| 판정 | Spearman ρ (95% 구간) | 우열 일치율 (95% 구간) |
|---|---|---|
| Sonnet · 텍스트만 | **0.36** (0.12 ~ 0.58) | **0.63** (0.56 ~ 0.71) |
| Sonnet · 이미지 포함 | 0.31 (0.08 ~ 0.53) | 0.61 (0.52 ~ 0.69) |
| Opus · 텍스트만 | 0.31 (0.06 ~ 0.53) | 0.60 (0.53 ~ 0.67) |
| Opus · 이미지 포함 | 0.30 (0.05 ~ 0.52) | 0.60 (0.52 ~ 0.67) |
| 참고: 평가자 본인 재평가 (8개 말풍선) | 0.69 | 같은 점수 71% |

우열 일치율은 같은 말풍선의 두 번역 중 어느 쪽이 나은지를 사람과 같게 고른 비율입니다(사람이 동점을 준 쌍 제외, 76쌍).

**1. 판정은 사람 판단과 약하게만 맞았습니다.** 네 판정 모두 ρ 0.30~0.36으로, 평가자가 스스로를 다시 평가했을 때의 일관성(0.69)에 한참 못 미칩니다. 판정 점수를 사람 점수 대신 그대로 쓰기는 어렵습니다.

**2. 판정은 "어색함"을 거의 잡지 못했습니다.** 판정은 120개 중 70~77%에 5점을 줬고, 사람은 48%였습니다. 점수 차가 2점 이상 난 사례 대부분이 사람은 "뜻은 맞지만 한국어로 어색하다"며 3점을 주고 판정은 5점을 준 경우였습니다(예: 「정말로 우주까지 올라간 걸까요」, 「그 불쌍한 건맨은...」).

**3. 말투 오류는 판정이 오히려 더 일관되게 잡았습니다.** 인물 관계표에 "소노야마는 존댓말"이라고 적힌 장면에서 반말 번역(「아, 아냐!」)을 판정 4개는 모두 2~3점으로 깎았지만 평가자는 5점을 줬습니다. 사람도 설정을 놓칠 수 있고, 규칙이 명확한 항목은 판정이 보조 검수로 쓸모 있다는 뜻입니다.

**4. 인물 관계표를 주자 일치도가 조금 올랐습니다.** 관계표 없이 돌린 첫 판정은 ρ 0.24~0.29였고, 관계표를 준 판정은 0.30~0.36이었습니다. 구간이 겹쳐서 확정할 수는 없지만, 네 판정 모두 같은 방향이었습니다.

**5. 이미지를 보여 줘도 나아지지 않았습니다.** 같은 모델에서 이미지 포함과 텍스트만의 차이는 ±0.05 안이었습니다. Kimura & Suzuki의 "이미지 판정이 항상 낫지는 않다"는 결론과 같은 방향입니다. 이 데이터에서는 그림보다 인물 관계 같은 설정 정보가 더 중요했습니다.

**6. 시스템 순위는 대체로 맞았습니다.** 사람은 S1(Opus · 이미지) > S3(Sonnet · 한 줄씩) > S2(Haiku · 이미지) 순으로 평가했고, 판정 4개 중 3개가 같은 순위를 냈습니다. 개별 말풍선 점수는 믿기 어려워도 시스템 평균 비교에는 쓸 여지가 있습니다.

### 다음에 해 볼 것

- 판정 기준에 "자연스러운 한국어인지"를 따로 점수로 떼어, 어색함을 놓치는 문제가 줄어드는지 확인
- 평가자를 2명 이상으로 늘려 사람끼리의 일치도를 기준선으로 삼기
- 작품 단위 인물 관계표 · 용어집을 번역 단계에도 넣어 말투 오류가 줄어드는지 확인

## 한계

- 평가자 1명, 말풍선 40개라 구간이 넓습니다. 결론보다 방법을 보여 주는 규모입니다.
- 평가자는 일본어 대신 공식 영어 번역으로 뜻을 확인했고, 판정 모델은 참조 없이 원문만 봤습니다. 영어와 일본어는 말풍선 사이 문장 나눔이 다른 곳이 있습니다(예: boureisougi p.33).
- 인물 관계표는 작성자가 앞쪽 대사와 그림으로 정리한 것이라, 원작 설정과 다를 수 있습니다.
- 번역 3개가 모두 Claude 계열이라 모델 계열 간 차이는 다루지 않습니다.

## 데이터 출처

[OpenMantra](https://github.com/mantra-inc/open-mantra-dataset): Hinami et al., *Towards Fully Automated Manga Translation*, AAAI 2021. CC BY-NC 4.0. `data/eval_set.json`의 일본어 원문 · 영어 번역은 이 라이선스(비상업 · 출처 표시)를 따르며, 페이지 이미지는 저장소에 포함하지 않습니다.

## 파일

- `data/eval_set.json` 평가셋(말풍선 위치 · 일본어 원문 · 공식 영어 번역), `data/context.json` 인물 관계표
- `runs/translate_S*.json` 번역 결과, `runs/judge_*.json` 판정 결과, `runs/blind_key.json` · `human_key.json` 시스템 가림 키
- `results/human_ratings.json` 사람 평가 원본(점수 · 태그 · 근거), `results/summary.json` 일치도, `results/disagreements.json` 2점 이상 어긋난 사례
